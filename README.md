# 🚌 버스 하차 안전 시스템

> 버스에서 내리는 승객과 뒤에서 달려오는 오토바이·자전거의 충돌을 AI로 미리 감지해, 경보음으로 승객에게 알리는 시스템

- 발표일: 2026년 12월 18일 (D-day)
- 팀원: 오연주, 성효진, 김태연, 윤승현

---

## 1. 문제 정의

### 어떤 문제인가?
버스가 정류장에 서면 버스와 인도 사이에 좁은 틈이 생깁니다. 이 틈으로 **오토바이, 자전거, 전동킥보드가 빠르게 지나가다가 막 내리는 승객과 부딪히는 사고**가 발생합니다.

### 왜 일어나는가?
- 승객은 내릴 때 **발밑과 앞만 보고**, 뒤에서 오는 차량은 잘 보지 않습니다.
- 버스 기사는 사이드미러로 확인하지만, **사각지대**가 있고 승객이 많으면 일일이 보기 어렵습니다.
- 이륜차는 크기가 작고 빨라서 **눈에 잘 띄지 않습니다.**

### 무엇을 해결하는가?
버스 뒤쪽 카메라가 달려오는 물체를 AI로 인식하고, **충돌이 예상되면 하차하는 승객에게 바로 알려서** 한 걸음 멈추게 합니다.

---

## 2. 유즈케이스 시나리오

### 예상 상황
- 버스가 인도에서 **약 1.8m 떨어진 차로**에 정차합니다.
- 승객이 **뒷문**으로 내려 버스와 인도 사이의 **틈**을 지나 인도로 걸어갑니다.
- 이때 오토바이가 버스 뒤쪽에서 **버스와 인도 사이 틈**으로 달려와 승객과 부딪힙니다.

→ 그래서 카메라 화면에서 **버스와 인도 사이 틈을 "감지 구역"**으로 정하고, **이 구역으로 들어오는 물체만** 위험 판단 대상으로 봅니다.

| # | 상황 | 시스템 동작 | 기대 결과 |
|---|---|---|---|
| UC1 | 뒷문 열림, 틈에 아무것도 없음 | 경고 없음 | 승객이 평소처럼 하차 |
| UC2 | 뒷문 열림, **오토바이가 버스 뒤에서 틈으로 빠르게 접근** | 충돌 예상 시간 계산 → **경보음** 작동 | 승객이 멈추고 오토바이가 지나간 뒤 하차 |
| UC3 | 뒷문 열림, 오토바이가 **틈이 아닌 바깥 차로**로 지나감 | 감지 구역 밖이므로 경고 없음 | 승객과 부딪힐 일이 없는 차량 때문에 경보가 울리지 않음 |
| UC4 | 뒷문 열림, 자전거·킥보드가 틈으로 **천천히** 접근 | 충돌 예상 시간이 길면 경고 없음, 짧아지면 경고 | 느린 물체에 미리 놀라지 않고, 가까워지면 경고 |
| UC5 | 문 닫힘 (운행 중) | 하차 중이 아니므로 경고 없음 | 운행 중 오작동 방지 |

**주요 사용자**: 하차하는 승객 (경고를 받는 사람), 버스 기사 (상태를 확인하는 사람)

## 4. High Level Design

```
[입력]                   [AI 처리 - 노트북]                          [출력]

후면 카메라 ──▶ ① 객체 탐지 (YOLO, OpenVINO / NPU)
                        │  오토바이, 자전거, 킥보드, 사람
                        ▼
                ② 감지 구역 필터 (버스와 인도 사이 틈 안의 물체만 남김)
                        │
                        ▼
                ③ 객체 추적 (같은 물체를 프레임마다 따라감)
                        │
                        ▼
                ④ 접근 속도 · 충돌 예상 시간 계산
                        │
문 열림 센서 ──▶ ⑤ 위험 판단 ─────────────────────────▶ 경보음 (부저)
(스위치)                 │  "뒷문 열림 + 틈 안 물체 + 충돌 예상 3초 이내"
                        │   → 위험
                        ▼
                ⑥ 기록 · 관제 화면 (경고 횟수, 위험했던 순간 저장)
```

### 구성 요소

| 구분 | 사용 기술 / 부품 |
|---|---|
| 객체 탐지 | YOLO (사전학습 모델) + OpenVINO 변환 |
| 가속기 | 실시간 추론은 **NPU** (버스 전원을 쓰는 상시 감시라 저전력이 중요), 성능 비교용으로 CPU/GPU 측정 |
| 하드웨어 제어 | 아두이노 또는 ESP32 (노트북과 시리얼 통신) |
| 출력 장치 | 부저 |
| 입력 장치 | 후면 카메라, 문 열림 스위치 |
| 시연 환경 | 자율주행 경진대회에서 사용하던 **메카넘휠 로봇차를 버스 역할**로 사용, 장난감 오토바이·자전거로 접근 상황 연출 |
| 협업·품질 | GitHub Milestone, Issue, PR 리뷰, GitHub Actions (pytest + ruff) |

### 위험 판단 방법 (초안)
- 카메라 화면에 **버스와 인도 사이 틈을 다각형 구역으로 미리 지정**하고, 이 구역 안의 물체만 판단합니다. (바깥 차로로 지나가는 차량은 제외)
- 물체 상자(bounding box)가 **빠르게 커질수록** 가까이, 빠르게 다가오는 것으로 봅니다.
- 상자 크기 변화로 **충돌 예상 시간(TTC, Time To Collision)**을 계산합니다.
- 뒷문이 열려 있고, 틈 안의 물체의 TTC가 기준값(예: 3초)보다 짧으면 **위험**으로 판단합니다.

## 7. 향후 계획 (MVP 이후)
- **문 잠금 연동**: 위험할 때 서보 모터로 문 열림을 잠시 늦추기
- **뒤차 경고**: 버스 뒤쪽 경고등으로 이륜차 운전자에게도 알리기
- **위험 정류장 지도**: 경고가 자주 울린 정류장을 기록해 정차 위치 개선에 활용
- **야간·우천 대응**: 어두운 환경과 비 오는 날의 인식 성능 개선
